# 全仓目录结构与模块说明

更新时间：2026-07-14

## 1. 项目概览

`paper2code` 是一个本地单用户论文复现 Agent，当前包含执行内核、API 控制面和 Web 控制台：

- `codes/`
  - 负责论文处理、代码生成、评测和自动修复的 pipeline。
- `web_api/`
  - 为当前 WebUI 提供 FastAPI 后端，负责 settings、任务、日志和产物访问。
- `web_ui/`
  - 已实现的 React + Vite 控制台，负责 settings、任务创建、状态/日志/产物浏览和 repo 下载。

典型链路：

```text
浏览器 / WebUI
  -> FastAPI
  -> PDF 上传
  -> .local/uploads/<job_id>/
  -> runs/<job_id>/
  -> codes/run_pipeline.py
  -> repo / results / logs / run_status.json / run_summary.json
```

## 2. 目录结构

| 路径 | 说明 |
|---|---|
| `codes/` | pipeline 主逻辑、评测逻辑、状态写入工具 |
| `web_api/` | FastAPI 路由、settings 存储、任务服务、日志服务、产物服务 |
| `web_ui/` | React + Vite 本地控制台；构建产物由 FastAPI 同源托管 |
| `tests/` | API 契约、安全边界、状态容错、进程生命周期、fallback 相关测试 |
| `docs/adr/` | 架构决策记录 |
| `docs/engineering/` | 测试、构建和仓库卫生基线 |
| `docs/info/` | 仓库结构与模块说明 |
| `docs/prompt/change_logs/` | 工程化 change log |
| `.local/` | 本地 settings 与上传缓存，不应提交 |
| `runs/` | 任务运行时目录，不应提交 |

## 3. 核心模块

### `codes/`

- `codes/run_pipeline.py`
  - pipeline 统一入口，负责 stages 编排、任务状态写入、`skip_mineru` 输入校验、auto-refine 调度。
- `codes/eval.py`
  - 评测与 fallback 链处理，记录实际使用的评测模型和剩余 fallback 模型。
- `codes/utils.py`
  - JSON 容错读取、原子写入、repo/eval 状态路径 helper。

### `web_api/`

- `web_api/main.py`
  - FastAPI 路由定义和参数边界。
- `web_api/errors.py`
  - 统一错误响应格式、稳定错误码、异常处理器。
- `web_api/job_service.py`
  - 上传 PDF、启动和取消 pipeline、归一化 job 状态、处理进程生命周期语义。
- `web_api/artifact_service.py`
  - 列出任务、汇总 artifacts、repo 文件树、repo 文件预览、repo zip 下载。
- `web_api/log_service.py`
  - 日志列表与日志尾部读取。
- `web_api/settings_store.py`
  - `.local/web_settings.json` 的容错读写和脱敏状态导出。
- `web_api/path_security.py`
  - `job_id` 校验与路径归属判断。
- `web_api/json_io.py`
  - JSON 原子写入和损坏 JSON 容错读取。
- `web_api/schemas.py`
  - Pydantic 请求/响应 schema。

## 4. 运行时目录

每个任务使用独立目录：

```text
runs/<job_id>/
  logs/
    00_web_api_pipeline.log
    *.log
  repo/
  results/
  .downloads/
    <job_id>_repo_<uuid>.zip
  run_status.json
  run_summary.json
```

`.local/uploads/<upload_id>/document.pdf` 保存 Web API 分块写入的 PDF；目录名和文件名均由服务端生成。

## 5. FastAPI 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/health` | 健康检查 |
| `GET` | `/api/v1/session` | 建立本地会话并返回 CSRF token |
| `POST` | `/api/v1/settings` | 保存本地 Web settings |
| `GET` | `/api/v1/settings/status` | 只返回布尔配置状态 |
| `POST` | `/api/v1/uploads` | 分块接收 PDF，返回 `upload_id` |
| `GET` | `/api/v1/jobs` | 列出历史任务 |
| `POST` | `/api/v1/jobs` | 使用 `upload_id` 启动任务 |
| `GET` | `/api/v1/jobs/{job_id}` | 返回任务详情与状态 |
| `GET` | `/api/v1/jobs/{job_id}/summary` | 返回任务摘要 |
| `GET` | `/api/v1/jobs/{job_id}/artifacts` | 返回 repo/results/logs 汇总 |
| `GET` | `/api/v1/jobs/{job_id}/repo/tree` | 返回 repo 文件树 |
| `GET` | `/api/v1/jobs/{job_id}/repo/file` | 预览 repo 文本文件 |
| `GET` | `/api/v1/jobs/{job_id}/export` | 下载 repo zip |
| `GET` | `/api/v1/jobs/{job_id}/logs` | 列出日志或读取指定日志内容 |
| `POST` | `/api/v1/jobs/{job_id}/cancel` | 取消当前 FastAPI 实例仍持有的活跃任务 |

`/jobs` 及 `/jobs/{job_id}` 是 SPA document 路由，不再根据 `Accept` 返回 JSON。

## 6. 当前 API 契约

### 统一错误格式

项目主动抛出的错误统一返回：

```json
{
  "error": {
    "code": "settings_not_configured",
    "message": "API settings are not configured.",
    "details": {}
  }
}
```

当前主要稳定错误码：

- `settings_not_configured`
- `job_not_found`
- `job_not_cancelable`
- `invalid_job_id`
- `invalid_upload`
- `invalid_parameter`
- `invalid_repo_path`
- `repo_not_available`
- `log_not_found`
- `file_too_large`
- `binary_file_not_supported`
- `unsupported_file_type`
- `artifact_not_available`
- `internal_error`

请求验证错误也使用以上 JSON envelope，状态码为 422。

### Job 状态语义

前端应稳定依赖以下字段：

- `job.status`
  - `queued | running | completed | failed | canceled | unknown`
- `job.process_state`
  - `active | finished | detached | orphaned | none`
- `job.cancelable`
  - `true | false`
- `job.cancel_unavailable_reason`
  - `already_finished | detached_after_restart | orphaned_process | process_not_registered`

约束：

- `detached` / `orphaned` 只出现在 `process_state`，不混入业务 `status`
- `GET /api/v1/jobs` 和 `GET /api/v1/jobs/{job_id}` 都返回以上核心字段
- 服务重启后，旧进程只会显示为 `detached` 或 `orphaned`，不会被误报成可取消

### 关键接口语义

- `GET /api/v1/settings/status`
  - settings 缺失、空文件、损坏、结构非法时都返回 `configured=false`
  - 不回显 API key
- `POST /api/v1/uploads`
  - 默认最多 100 MiB；按实际读取字节计数，不信任 `Content-Length`
  - 非 PDF 扩展名：`415 + unsupported_file_type`
  - 伪 PDF 内容：`400 + invalid_upload`
- `POST /api/v1/jobs`
  - settings 未配置：`400 + settings_not_configured`
  - `ref_based`：`422 + feature_not_supported`
  - 参数越界或 `pdf_markdown_path` 非法：`400 + invalid_parameter`
- `GET /api/v1/jobs`
  - 单个 run 状态 JSON 损坏不会拖垮整个列表
  - 列表项返回稳定 `status/process_state/cancelable/cancel_unavailable_reason`
- `GET /api/v1/jobs/{job_id}`
  - job 不存在：`404 + job_not_found`
  - `job_id` 非法：`400 + invalid_job_id`
  - 状态文件损坏：返回 `status=unknown`，不返回 500
- `POST /api/v1/jobs/{job_id}/cancel`
  - 已完成、detached、orphaned、未注册进程：`409 + job_not_cancelable`
- `GET /api/v1/jobs/{job_id}/logs`
  - job 存在但无日志：`200 + logs=[]`
  - 指定日志不存在：`404 + log_not_found`
  - 非法日志名：`400 + invalid_repo_path`
- `GET /api/v1/jobs/{job_id}/artifacts`
  - job 存在但 repo/results/logs 未生成时返回可解释的 200 结果，不返回 500
- `GET /api/v1/jobs/{job_id}/repo/file`
  - 路径穿越：`400 + invalid_repo_path`
  - repo 不存在：`404 + repo_not_available`
  - 文件过大：`413 + file_too_large`
  - 二进制或非 UTF-8 预览不支持：`415`
- `GET /api/v1/jobs/{job_id}/export`
  - job 不存在：`404 + job_not_found`
  - repo 不存在：`404 + repo_not_available`
  - 未预期内部异常：`500 + internal_error`

## 7. 安全与边界

当前已实现的边界：

- `job_id` 禁止目录穿越、绝对路径、Windows 盘符和非法字符
- `repo/file` 仅允许白名单文本扩展名，最大 2 MiB，拒绝二进制与非 UTF-8 预览
- `logs` 只允许当前 job `logs/` 目录下的单层 `.log` 文件
- `skip_mineru=true` 时，`pdf_markdown_path` 必须存在、必须是 Markdown 文件、且必须位于 `runs/` 下
- 错误响应不返回 API key、完整环境变量或敏感本地绝对路径
- Host 仅允许 `localhost`、`127.0.0.1`、`[::1]` 和显式配置值
- 所有状态变更请求校验 Origin/Referer、`Sec-Fetch-Site` 和 CSRF token
- API 响应使用 `Cache-Control: no-store`；SPA document 使用 `no-cache`

## 8. 已知限制

- 当前状态和摘要使用 JSON/文件存储，尚未实现 SQLite
- 当前 WebUI 每 2 秒轮询，尚未实现 SSE 或 WebSocket
- 只支持单个 FastAPI worker；多 worker 会分裂内存中的进程登记
- `.local/web_settings.json` 仍为本地明文存储，不等于磁盘加密
- `pdf_markdown_path` 当前限制到 `runs/`，尚未进一步收紧到当前 job 子目录
- `.downloads/` 下历史 zip 暂无自动清理策略
- 服务重启后不会重新接管 detached 进程，只会暴露正确状态语义
