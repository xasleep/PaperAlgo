# 全仓目录结构与模块说明

更新时间：2026-07-22

## 1. 项目概览

`paper2code` 是一个本地单用户论文复现 Agent，当前包含执行内核、API 控制面和 Web 控制台：

- `codes/`
  - 负责论文处理、代码生成、评测和自动修复的 pipeline。
- `web_api/`
  - 为当前 WebUI 提供 FastAPI 后端，负责 settings、任务、日志和产物访问。
- `web_ui/`
  - 已实现的 React + Vite 控制台，负责 settings、任务创建、状态/日志/产物浏览和 repo 下载。

典型链路：

```text
浏览器 / WebUI
  -> FastAPI
  -> PDF 上传
  -> .local/uploads/<upload_id>/
  -> runs/<job_id>/
  -> legacy FastAPI launcher / sqlite 独立 Worker
  -> codes/run_pipeline.py
  -> repo / results / logs / run_status.json / run_summary.json
```

## 2. 目录结构

| 路径 | 说明 |
|---|---|
| `codes/` | pipeline 主逻辑、评测逻辑、状态写入工具 |
| `web_api/` | FastAPI 路由、settings 存储、任务服务、日志服务、产物服务 |
| `web_ui/` | React + Vite 本地控制台；构建产物由 FastAPI 同源托管 |
| `tests/` | API 契约、安全边界、状态容错、进程生命周期、fallback 相关测试 |
| `docs/adr/` | 架构决策记录 |
| `docs/engineering/` | 测试、构建和仓库卫生基线 |
| `docs/info/` | 仓库结构与模块说明 |
| `docs/prompt/change_logs/` | 工程化 change log |
| `.local/` | 本地 settings 与上传缓存，不应提交 |
| `runs/` | 任务运行时目录，不应提交 |

## 3. 核心模块

### `codes/`

- `codes/run_pipeline.py`
  - pipeline 统一入口，负责 stages 编排、任务状态写入、`skip_mineru` 输入校验、auto-refine 调度；SQLite Worker 可显式启用 checkpoint adapter，legacy 默认关闭。
- `codes/checkpoint_protocol.py`
  - PR-04B 固定 checkpoint schema、连续阶段链/唯一 stage-1 分支/attempt 与 resume 约束、64 KiB 限制、原子文件替换、相对路径安全校验、完整恢复状态闭包、TaskManifest Planning 指纹绑定和 artifact size/SHA-256 复核。
- `codes/eval.py`
  - 评测与 fallback 链处理，记录实际使用的评测模型和剩余 fallback 模型。
- `codes/utils.py`
  - JSON 容错读取、原子写入、repo/eval 状态路径 helper。
- `codes/provider_registry.py`
  - 加载并按封闭 schema 严格校验版本化 Provider/Model 清单；根、Provider、Model、Pricing、request options 的未知字段和非法类型/范围均被拒绝。显式绑定 provider/model、凭据环境变量名和必要 base URL，并在发送前执行 `max_n`、context/output、JSON Schema、timeout/retry/concurrency 门禁。Contract 及嵌套 options 深度不可变，配置错误使用脱敏稳定代码且不包含密钥。
- `codes/providers.v1.json`
  - 默认 Registry 数据。每个模型完整记录能力、限制和价格状态；未经核实的 context/价格保持 `null`/`unknown`，不会由代码猜测。
  - 默认模型 ID 只来自 2026-08-06 复核的官方清单；`base_url=null` 是要求显式 endpoint/地域配置的策略，而不是把官方地址标记为未知。
- `codes/run_pipeline.py`
  - 阶段子进程环境从最小系统 allowlist 构造；角色凭据优先，否则只映射所选 ModelContract 的 Provider 原生凭据，隔离未选 Provider 与 reproduce/evaluation 两个角色。

### `web_api/`

- `web_api/main.py`
  - FastAPI 路由定义和参数边界。
- `web_api/errors.py`
  - 统一错误响应格式、稳定错误码、异常处理器。
- `web_api/job_service.py`
  - 保存上传、构造 Pipeline 命令与最小环境、生成/验证非敏感 Provider 选择快照、归一化 job 状态，并处理 legacy runtime 的进程生命周期；sqlite runtime 的启动和取消由 Repository 与独立 Worker 完成。
- `web_api/artifact_service.py`
  - 列出任务、汇总 artifacts、repo 文件树、repo 文件预览、repo zip 下载。
- `web_api/log_service.py`
  - 日志列表与日志尾部读取。
- `web_api/settings_store.py`
  - `.local/web_settings.json` 的容错读写和脱敏状态导出。
- `web_api/path_security.py`
  - `job_id` 校验与路径归属判断。
- `web_api/json_io.py`
  - JSON 原子写入和损坏 JSON 容错读取。
- `web_api/database.py`
  - 标准库 SQLite 连接、编号 migration 及并发初始化；保持 WAL、`foreign_keys=ON`、`busy_timeout=5000`，migration 在显式事务中提交或完整回滚。
- `web_api/job_state.py`
  - execution / evaluation / quality 三轴状态机与转换验证；execution 终态包括 completed、failed 和 canceled，失败原因另存为稳定 `failure_code`。
- `web_api/job_repository.py`
  - SQLite job Repository、幂等创建、Provider/Model/fallback/Registry version/Contract SHA-256 非敏感选择快照、`worker_id + instance_token` 全局 lease、`BEGIN IMMEDIATE` 原子领取、幂等取消命令、进程 launch state/身份元数据、阶段 attempt、受限恢复计数、进程历史、version 乐观锁和整数微美元成本记录。数据库不保存 API key、base URL、完整命令或环境变量。
- `web_api/worker.py`
  - `python -m web_api.worker` 入口、单并发领取、Provider 选择快照门禁、进程 heartbeat、命令驱动取消、进程级 reconciliation 和默认最多 1 次的 checkpoint 恢复；设置选择、Registry version/指纹不匹配或快照缺失时在 `Popen` 前以 `provider_settings_changed` 失败，同一选择的凭据轮换可以继续。在线非零退出与重启后 confirmed-missing 共用同一恢复契约，exit 0 不恢复，晚到 cancel 不得覆盖自然退出或启动恢复，未登记完整的进程身份会 fail closed 且绝不恢复。
- `web_api/process_identity.py`
  - PID/create-time 与 process group 校验、进程树快照、优雅终止和验证后的树级强制终止；Windows 在同一句柄上验证、终止并有界等待，不依赖 `taskkill /T /F`。
- `web_api/schemas.py`
  - Pydantic 请求/响应 schema。

## 4. 运行时目录

每个任务使用独立目录：

```text
runs/<job_id>/
  checkpoints/                 # sqlite runtime 的版本化阶段边界
    checkpoint-<sequence>-<stage>-<attempt>.json
  logs/
    00_web_api_pipeline.log  # legacy
    00_worker_pipeline.log   # sqlite
    *.log
  repo/
  results/
  .downloads/
    <job_id>_repo_<uuid>.zip
  run_status.json
  run_summary.json
```

`.local/uploads/<upload_id>/document.pdf` 保存 Web API 分块写入的 PDF；目录名和文件名均由服务端生成。

## 6. 当前 API 契约

### 统一错误格式

项目主动抛出的错误统一返回：

```json
{
  "error": {
    "code": "settings_not_configured",
    "message": "API settings are not configured.",
    "details": {}
  }
}
```

当前主要稳定错误码：

- `settings_not_configured`
- `job_not_found`
- `job_not_cancelable`
- `invalid_job_id`
- `invalid_upload`
- `invalid_parameter`
- `invalid_repo_path`
- `repo_not_available`
- `log_not_found`
- `file_too_large`
- `binary_file_not_supported`
- `unsupported_file_type`
- `artifact_not_available`
- `internal_error`

请求验证错误也使用以上 JSON envelope，状态码为 422。

### Job 状态语义

前端应稳定依赖以下字段：

- `job.status`
  - `queued | running | completed | failed | canceled | unknown`
- `job.process_state`
  - `active | finished | detached | orphaned | none`
- `job.cancelable`
  - `true | false`
- `job.cancel_unavailable_reason`
  - `already_finished | detached_after_restart | orphaned_process | process_not_registered | process_identity_unresolved`

约束：

- `detached` / `orphaned` 只出现在 `process_state`，不混入业务 `status`
- `GET /api/v1/jobs` 和 `GET /api/v1/jobs/{job_id}` 都返回以上核心字段
- legacy FastAPI 重启后，旧 legacy 进程只会显示为 `detached` 或 `orphaned`，不会被误报成可取消
- API 重启不影响独立 SQLite Worker 及其 Pipeline；在线本地非零退出与 SQLite Worker 重启时确认 registered 进程死亡使用同一资格判断，只有完整登记身份、有效 lease/fencing、无取消、完整 completed 状态闭包校验通过且未超出预算时才执行一次受限恢复
- sqlite job 可返回 `stage`、`stage_attempt`、`last_checkpoint_stage`、`recovery_count`、`recovery_status` 与稳定的 `recovery_error_code`；不会返回 checkpoint 内容、PID/create time、launch/instance token 或完整命令

### 关键接口语义

- `GET /api/v1/settings/status`
  - settings 缺失、空文件、损坏、结构非法时都返回 `configured=false`
  - 不回显 API key
- `GET /api/v1/providers`
  - 始终返回 JSON 与 `Cache-Control: no-store`，忽略浏览器 `Accept: text/html` 的 SPA 偏好
  - 仅返回 Registry version、active provider/model ID 与非敏感能力状态；无模型 Provider 不可选
  - 不返回 settings、API key、base URL、环境、Prompt、响应或命令
- `POST /api/v1/uploads`
  - 默认最多 100 MiB；按实际读取字节计数，不信任 `Content-Length`
  - 非 PDF 扩展名：`415 + unsupported_file_type`
  - 伪 PDF 内容：`400 + invalid_upload`
- `POST /api/v1/jobs`
  - settings 未配置：`400 + settings_not_configured`
  - `ref_based`：`422 + feature_not_supported`
  - 参数越界或 `pdf_markdown_path` 非法：`400 + invalid_parameter`
  - sqlite 模式下新 job 原子保存非敏感 Provider 选择快照；相同 `Idempotency-Key` 与相同请求返回原 job 和原快照，不因当前 settings 变化而重绑定；不同请求返回 `409 + idempotency_conflict`
- `GET /api/v1/jobs`
  - 单个 run 状态 JSON 损坏不会拖垮整个列表
  - 列表项返回稳定 `status/process_state/cancelable/cancel_unavailable_reason`
- `GET /api/v1/jobs/{job_id}`
  - job 不存在：`404 + job_not_found`
  - `job_id` 非法：`400 + invalid_job_id`
  - 状态文件损坏：返回 `status=unknown`，不返回 500
- `POST /api/v1/jobs/{job_id}/cancel`
  - legacy 的已完成、detached、orphaned、未注册进程：`409 + job_not_cancelable`
  - sqlite 的取消只创建幂等命令，不由 FastAPI 直接 kill；`identity_unresolved` 返回 `409 + job_not_cancelable`，不会创建新命令或伪装成 canceled
- `GET /api/v1/jobs/{job_id}/logs`
  - job 存在但无日志：`200 + logs=[]`
  - 指定日志不存在：`404 + log_not_found`
  - 非法日志名：`400 + invalid_repo_path`
- `GET /api/v1/jobs/{job_id}/artifacts`
  - job 存在但 repo/results/logs 未生成时返回可解释的 200 结果，不返回 500
- `GET /api/v1/jobs/{job_id}/repo/file`
  - 路径穿越：`400 + invalid_repo_path`
  - repo 不存在：`404 + repo_not_available`
  - 文件过大：`413 + file_too_large`
  - 二进制或非 UTF-8 预览不支持：`415`
- `GET /api/v1/jobs/{job_id}/export`
  - job 不存在：`404 + job_not_found`
  - repo 不存在：`404 + repo_not_available`
  - 未预期内部异常：`500 + internal_error`

## 7. 安全与边界

当前已实现的边界：

- `job_id` 禁止目录穿越、绝对路径、Windows 盘符和非法字符
- `repo/file` 仅允许白名单文本扩展名，最大 2 MiB，拒绝二进制与非 UTF-8 预览
- `logs` 只允许当前 job `logs/` 目录下的单层 `.log` 文件
- `skip_mineru=true` 时，`pdf_markdown_path` 必须存在、必须是 Markdown 文件、且必须位于 `runs/` 下
- checkpoint JSON 使用固定字段/版本/阶段白名单并限制为 64 KiB；链必须从 sequence 1 连续推进且 stage/attempt/resume 无冲突。artifact 只接受 run 目录内的相对 POSIX 路径，拒绝 traversal、绝对路径、symlink、junction/reparse point 和硬链接；恢复复核完整状态闭包的 size/SHA-256，并要求 TaskManifest 与可信 Planning 边界指纹一致
- 错误响应不返回 API key、完整环境变量或敏感本地绝对路径
- Host 仅允许 `localhost`、`127.0.0.1`、`[::1]` 和显式配置值
- 所有状态变更请求校验 Origin/Referer、`Sec-Fetch-Site` 和 CSRF token
- API 响应使用 `Cache-Control: no-store`；SPA document 使用 `no-cache`

## 8. 已知限制

- 默认 legacy runtime 继续使用 JSON/文件状态，FastAPI 重启后不能接管原进程；PR-04B checkpoint 和受限恢复仅由 sqlite Worker 启用
- sqlite running job 的进程身份未登记完整时会进入 `identity_unresolved` 隔离态，保持 running 并阻止新任务；系统不会按超时推断进程死亡，该状态可能需要人工检查并重启本地环境
- sqlite 恢复默认最多 1 次，只能从完整可信的 completed 阶段边界开始；running/failed/部分阶段从上一个边界所指向的阶段开头重跑，属于 stage-boundary at-least-once，可能重复 MinerU、Provider 请求、成本累计和文件写入，不保证 exactly-once 或任意语句级恢复
- checkpoint 缺失、校验失败、取消竞态或恢复预算耗尽会形成稳定失败而不是继续启动；本地 run 目录可能需要人工检查
- sqlite Worker 只把可预期的单 job 预启动错误写为 `process_launch_failed` 并继续轮询；数据库、lease、登记后不安全状态与未知异常仍 fail fast
- sqlite queued/running job 的 Provider 选择、Registry version 或 Contract 指纹与当前凭据配置不兼容，或旧行缺少快照时，在 `Popen` 前稳定失败为 `provider_settings_changed`；同一选择下只轮换 API key/base URL 允许继续，且这些值不进入 SQLite
- sqlite 取消由命令驱动；exit 0 正常完成，非零退出无取消时才考虑恢复，晚到 cancel 失败为 `already_finished`，只有有效取消窗口内身份匹配且完整进程树确认退出才写入 canceled
- sqlite runtime 提供后端 SSE job event stream 和持久化 job commands；当前 WebUI 仍每 2 秒轮询，尚未接入 EventSource，也没有 WebSocket
- 只支持单个 FastAPI worker；多 worker 会分裂内存中的进程登记
- `.local/web_settings.json` 仍为本地明文存储，不等于磁盘加密
- 当前部署边界仍是 Windows、本地单用户、`127.0.0.1`、单 FastAPI 与单 Worker；PR-07A 不实现多用户、公共互联网、分布式队列或 WebUI EventSource 接入
- `pdf_markdown_path` 当前限制到 `runs/`，尚未进一步收紧到当前 job 子目录
- `.downloads/` 下历史 zip 暂无自动清理策略
- legacy 服务重启后不会重新接管 detached 进程；sqlite Worker 的恢复仍要求 PID/create time/process group 已完整登记且确认死亡，不能宣称覆盖任意崩溃点的自动恢复
