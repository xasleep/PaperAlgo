# ADR 0003：任务事件优先使用 SSE 而非 WebSocket

- 状态：已接受（方向性决策，PR-00 未实现）
- 日期：2026-07-14

## 背景

当前 WebUI 每 2 秒轮询任务、日志和 artifact 接口。未来若加入服务端推送，主要数据流是 FastAPI 到浏览器的单向状态/日志通知；任务创建和取消仍通过普通 HTTP 请求完成。

## 决策

- 未来的实时任务事件传输优先采用 Server-Sent Events（SSE），不采用 WebSocket。
- SSE 只传递脱敏、有限大小的事件；不得包含 API key、完整 Prompt 或完整模型响应。
- REST API 继续作为任务状态的权威查询和恢复路径；断线重连后客户端应重新读取 REST 状态。
- PR-00 不新增 SSE endpoint，也不改变当前轮询行为。

## 后果

SSE 与单向事件流和普通 HTTP 基础设施匹配，客户端实现也较小。它不适合双向低延迟协议；若未来出现真实的双向需求，需要重新评审本 ADR。
